<threat_model>
Trust boundaries:
- Untrusted ROM bytes enter through `Cartridge`, then through `Bus::read8`.
- CPU instruction decode treats ROM bytes as data, never as host executable code.

STRIDE register:

| threat_id | category | component | disposition | mitigation_plan |
|-----------|----------|-----------|-------------|-----------------|
| CPU-01-T1 | Tampering | `Cpu::step` opcode input | mitigated | Read opcodes via `Bus::read8` only and return `CpuError::UnsupportedOpcode` for unsupported bytes. |
| CPU-01-T2 | Denial of Service | unsupported opcode handling | mitigated | Do not panic or loop; return a structured error with opcode and PC. |
| CPU-01-T3 | Information Disclosure | CPU diagnostics | accepted-low | Error text may include opcode and PC only; no filesystem paths or ROM contents are printed by core code. |

Block on: high severity threats. No high severity threats are expected in this foundation slice if unsupported opcodes are structured errors and core code has no console output.
</threat_model>
